# OpenCode への委任

OpenCode を下位エージェントとして使える。`opencode run` で作業を渡し、結果を受け取る。

- **委任は利用者が指示したときだけ行う。** 自分の判断で OpenCode に作業を渡さない。
- OpenCode 側には、下位エージェントとして呼ばれたときの指示 (`~/.config/opencode/AGENTS.md`) がある。

## 依頼の出し方

対象リポジトリのディレクトリで、stdin を閉じて実行する。

```sh
opencode run --auto --title "<短い作業名>" "【上位エージェントからの依頼】
<依頼文>" < /dev/null
```

- `--auto` を付ける。付けないと、shell など確認 (`ask`) が必要な操作を誰も承認できない。`--auto` は `deny` 以外の権限要求をすべて承認するので、確認が残っていた操作 (shell、作業ディレクトリ外へのアクセスなど) も実行されうる。commit や push を禁止しているのは OpenCode 側の指示だけなので、結果は必ず確かめる。
- 依頼文の先頭行は必ず `【上位エージェントからの依頼】` にする。OpenCode はこの行で下位エージェントとして呼ばれたと判断する。
- **stdin は必ず閉じる。** `opencode run` は、stdin が端末でないと EOF まで読み続けてから作業を始める。開いたままの stdin を渡すと、出力のないまま止まる。
  - Bash (Git Bash を含む): 末尾に `< /dev/null` を付ける。
  - PowerShell: `<` で stdin を閉じられない。Git Bash 経由 (`bash -c '...'`) で `< /dev/null` を付けて実行する。
- `timeout` などで実行時間の上限を付けない。正常に作業していても打ち切られる。
- 自分のコマンド実行ツールの上限で打ち切られないよう、バックグラウンドで実行し、終了を待つ。
- `opencode run` は、起動したバックグラウンドのジョブ (開発サーバーなど) が終わるまで終了しない。終わらない処理を起動させる依頼は出さない。

## モデル

- OpenCode Go のモデル (`opencode-go/...`) だけを使う。
- 通常は `-m` を付けず、設定の既定モデルを使う。
- 変える場合は `opencode models < /dev/null` で `opencode-go/` の一覧を確かめ、`-m opencode-go/<モデル名>` で指定する。

## 依頼文に含めること

OpenCode は途中で質問できず、利用者も介在しない。依頼文だけで作業できるように、次を含める。

- 目的と、その背景
- 作業の種類 (実装・調査・テスト・レビュー)
- 対象のファイルやディレクトリ、触ってはいけない範囲
- 守るべき制約 (使うライブラリ、既存の慣行など)
- 完了条件
- すでに分かっていること、除外済みの可能性

1回の依頼は1つの目的に絞る。続けて依頼するときは、最初の出力にあるセッション ID を `-s <ID>` で渡す。

- 同じファイルを触る依頼を並行して出さない。並行させるときは `--worktree` で作業場所を分ける。

## 結果の扱い

- 報告をそのまま信じない。変更は `git diff` で確かめ、必要な test は自分でも実行する。
- `git status` と `git log` で、commit や branch の変更など依頼していない操作がないかも確かめる。
- 依頼の範囲外の変更があれば、元に戻すか利用者に報告する。
- 利用者への報告では、OpenCode に任せた部分と、自分で確認した内容を分けて書く。
